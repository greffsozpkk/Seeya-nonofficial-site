# SEEYA ARCHIVE — v4.102

갤러리를 MUSIC과 같은 하위 메뉴 방식으로 분리했습니다. “사진”은 기존 사진 페이지, “캐릭터 이미지”는 별도 모음집 페이지로 이동합니다. 이전 아카이브 이미지 교체와 캐릭터 모음집 전체를 포함한 누적 업데이트입니다.

## 이번 업데이트 적용

1. GitHub Desktop에서 **Fetch origin → Pull origin**으로 최신 파일을 받습니다.
2. `SEEYA_v4_102_UPLOAD.zip`의 내용물을 저장소 최상위 폴더에 같은 경로로 복사합니다.
3. 변경 내역을 확인하고 **Commit → Push**합니다. 기존 Actions의 사이트 빌드와 Pages 배포 완료를 기다립니다.

이번 UPLOAD는 **v4.94~v4.101에서 바로 적용할 수 있는 누적본**입니다. 새 아카이브·모의고사 이미지 파일과 캐릭터 모음집 및 관련 페이지·스타일·날짜 기능·배치파일이 모두 들어 있습니다. 기존 아카이브·뉴스·사진·방문자 데이터와 생성 HTML은 덮어쓰지 않습니다. 이미지 주소에는 버전 표시를 붙여 이전 응답이 캐시에 남아도 새 주소로 요청합니다. FULL_BACKUP은 전체 보관용이며 로컬 확인을 위해 풀 필요는 없습니다.

앞으로도 UPLOAD는 직전 버전에서 바뀐 파일만 담지 않고, 이 소스 구조의 기준 버전(v4.94) 이후 필요한 소스·추가 이미지·실행 파일을 누적해 제공합니다. 지원 기준을 바꾸는 경우 README에 먼저 명시합니다. 업데이트 ZIP을 빈 폴더에 푸는 신규 설치 방식은 지원하지 않으며 기존 사이트 폴더에 덮어써야 합니다.

게임 선택은 `/game/`, 제목 맞히기는 기존 `/game/lyrics/`, 모의고사는 `/game/exam/`입니다. 모의고사의 내용은 `src/pages/exam.js`에서 추가할 수 있습니다.

| 내용 | 편집 위치 |

| 갤러리 사진 | `data/photos.json`, `images/gallery/` |

| 오늘 방문자 집계 | `data/visitors.json` — 자동 갱신 |

앞으로 버전별 아카이브 JSON이나 MD 파일을 새로 만들지 않습니다. `data/archive.json`에 새 고유 ID를 추가하거나 기존 기록을 수정하고 `CHANGELOG.md`에 변경 내역을 누적합니다. 같은 출연의 여러 곡·영상은 songs·additionalSources에 모읍니다. 날짜가 불명확하면 영상 게시일을 표시하고 dateBasis·note에 근거를 남깁니다. 발매·공개일, 첫 방송일, 공연 시즌도 따로 표시합니다. 팬 보관 자료의 날짜만 확인된 경우에는 잠정 표시를 유지합니다.

기존 별도 MD 문서는 CHANGELOG에 원문을 보관했습니다. 그 안의 과거 적용 방법·당시 수치·확인 대기 문구는 역사적 기록이며 현재 안내를 대체하지 않습니다. 현재 출처와 확정 여부는 아카이브 각 기록에 있습니다.

## 로컬 실행과 빌드

업데이트 ZIP을 **기존 사이트 폴더에 덮어쓴 다음 `serve-local.bat`을 실행**하세요. 최신 페이지 생성이 성공하면 http://127.0.0.1:8000/ 에서 미리보기를 시작합니다. 서버 창은 열어 두세요. 이전 미리보기 창이 열려 있으면 먼저 닫고 실행합니다.

Node.js는 한 번 설치해야 합니다. Node.js가 없으면 배치파일에서 설치 주소와 안내를 보여줍니다. 기존 Actions와 같은 Node 22를 사용할 수 있으며 Python이나 별도 npm 패키지는 필요 없습니다. 페이지 생성에 실패하면 예전 화면을 띄우지 않고 오류를 안내합니다. 로컬 서버는 브라우저 캐시를 사용하지 않도록 응답합니다.

직접 실행할 경우:

```sh
node build.js
node scripts/check.js
node scripts/serve.js 8000
```

`node scripts/serve.js`만 실행하면 포트 8080이며 이 명령 자체는 빌드하지 않습니다. 파일을 더블클릭하는 file:// 방식 대신 위 서버 주소를 사용하세요.

**생성된 HTML 직접 편집 금지.** 각 경로 index.html, 해시 파일명 assets/site.*·assets/lyric-quiz.*, sitemap.xml, build-manifest.json은 빌드 산출물입니다. 일반 링크로 이동하며 NEWS·ARCHIVE·GALLERY는 빌드 시 본문과 대체 데이터를 만들고 방문 후 최신 JSON을 읽습니다.

이전 해시 자산은 캐시된 HTML이 참조할 수 있어 유지합니다. 임의로 지우면 예전 페이지에서 퀴즈가 실행되지 않을 수 있습니다. 정리 도구는 이 파일들을 삭제하지 않습니다.

## 캐릭터 이미지 모음

GALLERY 상단의 “사진 / 캐릭터 이미지” 버튼으로 서로 다른 페이지를 이동합니다. 사진은 `/gallery/`, 캐릭터 이미지는 `/gallery/characters/`입니다. 사진 페이지에는 캐릭터 모음집을 함께 이어 붙이지 않습니다. 캐릭터 페이지에 11장의 그림을 표시하며, 클릭하면 원본 비율로 크게 볼 수 있습니다. 현재 메뉴는 선택 상태로 표시됩니다. 두 경로 모두 직접 접속·새로고침·브라우저 뒤로 가기·JS 미사용 이동을 지원합니다. 이전·다음 버튼, 좌우 방향키, 모바일 좌우 넘기기를 지원합니다. Escape 또는 닫기를 누르면 원래 카드로 돌아옵니다. “원본 보기”는 이미지 파일을 새 탭으로 엽니다.

그림 목록은 `src/data/character-gallery.json` 한 파일로 관리합니다. 각 항목은 고유 id, 제목, 이미지 주소, 실제 폭·높이, 사용 페이지 목록을 가집니다. 새 그림을 추가할 때 이 목록에도 등록하고 빌드하세요. 기존 이미지 파일을 그대로 참조하므로 모음집을 위해 같은 파일을 다시 복사하지 않습니다. JS가 꺼져 있거나 dialog가 지원되지 않는 브라우저에서는 카드를 누르면 이미지 원본으로 이동합니다.

새 아카이브 그림은 `images/archive/seeya-archive-room.png`입니다. 기존 `seeya-archive-pixel.png`는 삭제하지 않고 “ARCHIVE · 이전 그림”으로 모음집에 보관합니다. 모의고사는 최근 수정본을 사용합니다. 여러 페이지에서 함께 쓰는 동일 그림은 모음집에 한 번만 표시합니다.

## 오늘 날짜의 씨야

TODAY의 첫 콘텐츠로 지난 연도 중 같은 월·일의 아카이브 기록을 보여줍니다. 한국 시간(Asia/Seoul) 기준이며 올해 및 미래 일정은 과거 회고에서 제외합니다. 연도별 최신순으로 모으고, 일치하는 기록이 없으면 빈 기록 안내를 표시합니다.

기준 자료는 기존 `data/archive.json` 하나입니다. 날짜가 정확히 월·일까지 있는 기록만 사용합니다. 영상·기사 게시일 기준과 잠정 날짜는 기존 표시를 유지합니다. 날짜 미확인·공연 시즌·취소·예정·숨김 기록은 제외합니다. 같은 ID는 한 번만 표시하며 일정표 링크는 카드에 노출하지 않습니다.

빌드 시 `src/data/site.json`의 `snapshotDate` 기준 본문을 생성합니다. 접속하면 실제 한국 날짜와 최신 JSON으로 갱신하고, 페이지를 계속 열어 두면 자정 이후 최대 약 30초 내에 날짜를 바꿉니다. 백그라운드 탭은 다시 열 때 확인합니다. 네트워크 오류 시 마지막으로 불러온 자료 또는 빌드에 포함된 자료를 사용합니다. JS를 끈 환경에서는 빌드 기준 날짜의 본문을 보여줍니다.

아카이브 919건 자체를 바꾸거나 새 기록을 임의로 추가하지 않았습니다. 현재 자료에는 9월 13일의 지난 연도 기록이 없어서 이날은 빈 기록 안내가 나옵니다. 이후 해당 날짜의 과거 자료를 등록하면 자동으로 나타납니다.

## 검증과 배포 범위

`scripts/check.js`는 빌드 재현성·14개 경로 본문·JS 문법·로컬 링크와 아카이브 검사를 실행합니다. `scripts/check-archive.js`는 ID·날짜·출처, 필터·페이지 이동 및 주요 회차를 검사합니다. `scripts/check-on-this-day.js`는 한국 자정·윤년·날짜 일치·예정 및 날짜 미확인 기록 제외·게시일 표시를 검사하며 전체 검사에도 포함됩니다. 별도 브라우저 검사는 Edge와 Playwright 설치 환경에서 진행합니다.

사이트 실행에는 각 경로 HTML, assets/, images/, data/, 404.html, robots.txt, sitemap.xml이 필요합니다. GitHub에서 빌드하려면 src/, scripts/, build.js, .github/도 유지하세요. 운영 저장소의 CNAME·사진·자동화 데이터는 계속 보존합니다.

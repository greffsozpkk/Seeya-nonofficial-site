# SEEYA ARCHIVE — v4.108

MUSIC에 곡별 무대 모아보기를 추가했습니다. 14곡과 기존 45개 출연 기록을 연결하며, 곡 검색·앨범 필터·무대별 상세 화면을 제공합니다. 아카이브 원본 926건은 그대로 유지합니다.

## 이번 업데이트 적용

1. GitHub Desktop에서 **Fetch origin → Pull origin**으로 최신 파일을 받습니다.
2. `SEEYA_v4_108_UPLOAD.zip`의 내용물을 저장소 최상위 폴더에 같은 경로로 복사합니다.
3. 변경 내역을 확인하고 **Commit → Push**합니다. 기존 Actions의 사이트 빌드와 Pages 배포 완료를 기다립니다.

이번 UPLOAD는 **v4.94~v4.107에서 바로 적용할 수 있는 누적본**입니다. 새 아카이브·모의고사 이미지 파일과 캐릭터 모음집 및 관련 페이지·스타일·날짜 기능·배치파일이 모두 들어 있습니다. 이번 ZIP에는 총 926건의 `data/archive.json`이 포함됩니다. 기존 922건의 ID는 모두 유지하고 제천 시간표와 체크인 콘서트 영상 연결 2건만 보완했습니다. 뉴스·사진·방문자 데이터와 생성 HTML은 덮어쓰지 않습니다. 이미지 주소에는 버전 표시를 붙여 이전 응답이 캐시에 남아도 새 주소로 요청합니다. FULL_BACKUP은 전체 보관용이며 로컬 확인을 위해 풀 필요는 없습니다.

앞으로도 UPLOAD는 직전 버전에서 바뀐 파일만 담지 않고, 이 소스 구조의 기준 버전(v4.94) 이후 필요한 소스·추가 이미지·실행 파일을 누적해 제공합니다. 지원 기준을 바꾸는 경우 README에 먼저 명시합니다. 업데이트 ZIP을 빈 폴더에 푸는 신규 설치 방식은 지원하지 않으며 기존 사이트 폴더에 덮어써야 합니다.

게임 선택은 `/game/`, 제목 맞히기는 기존 `/game/lyrics/`, 모의고사는 `/game/exam/`입니다. 모의고사의 내용은 `src/pages/exam.js`에서 추가할 수 있습니다.

## 곡별 무대 모아보기

- 진입: MUSIC → 곡별 무대(`/music/stages/`). 곡 목록은 PC 3열·모바일 2열, 12곡씩 표시합니다. 상세 화면은 무대 6개씩 표시합니다.
- 검색·앨범·정렬, 무대 종류·연도·멤버 필터를 제공합니다. 선택 조건과 페이지 번호는 URL에 남아 새로고침과 뒤로 가기로 복원됩니다.
- 첫 공개 범위는 씨야 곡 14개, 기존 출연 45건의 영상 출처 50개입니다. 같은 출연에 여러 영상이 있어도 한 카드로 묶습니다. 영상은 YouTube의 원본 페이지를 새 탭으로 엽니다.
- 곡 메타데이터는 `src/data/stage-songs.json`, 출연 ID·기존 영상 URL·해당 곡 ID의 연결은 `src/data/stage-sources.json`에서 관리합니다. 실제 날짜·멤버·프로그램 등은 `data/archive.json`에서 읽습니다. 새 곡 추가 시 `src/data/routes.json`에 songId가 같은 상세 경로도 추가하세요.
- 곡별 연결은 기존 아카이브의 단일 곡 기록, 명시된 출처 곡명, 라이브 수록곡 설명을 바탕으로 작성했습니다. 영상 내용을 이번 작업에서 전부 재시청하거나 외부 영상의 현재 재생 가능 여부를 전수 검증한 것은 아닙니다. 수록곡이 불명확한 출처는 자동 배정하지 않습니다. `fFA8uMG8QVE`는 기존 결혼할까요/Hot Girl 기록에 중복되어 이번 목록에서 제외했습니다.
- `scope: multi`는 여러 곡 포함, `compilation`은 무대 모음의 기존 시간 링크입니다. 임의 타임스탬프를 만들지 않습니다. 단일 곡 연결은 `single`입니다. 예정 행사와 빌드 기준일 이후 기록은 표시하지 않습니다.
- 기존 아카이브의 관련곡에서 곡별 페이지로 이동하고, 상세 화면에서는 해당 아카이브 기록 한 건으로 돌아갈 수 있습니다. 검색어를 바꾸거나 초기화하면 전체 아카이브를 다시 탐색합니다.
- 새 페이지도 본문이 들어 있는 정적 HTML입니다. `node build.js`로 배포 산출물과 sitemap을 생성하고 `node scripts/check.js`로 확인합니다. **생성된 HTML 직접 편집 금지**. 로컬 확인은 기존 `serve-local.bat`이며 v4.107의 임시 폴더 미리보기 방식을 유지합니다.

## 로컬 실행과 빌드

업데이트 ZIP을 **기존 사이트 폴더에 덮어쓴 다음 `serve-local.bat`을 실행**하세요. 최신 페이지를 운영체제 임시 폴더에 생성한 뒤 http://127.0.0.1:8000/ 에서 미리보기를 시작합니다. 저장소의 HTML·해시 자산·manifest는 변경하지 않습니다. 이미지는 복사하지 않고 기존 폴더에서 읽습니다. 서버 창은 열어 두세요. 이전 미리보기 창이 열려 있으면 먼저 닫고 실행합니다.

Node.js는 한 번 설치해야 합니다. Node.js가 없으면 배치파일에서 설치 주소와 안내를 보여줍니다. 기존 Actions와 같은 Node 22를 사용할 수 있으며 Python이나 별도 npm 패키지는 필요 없습니다. 페이지 생성에 실패하면 예전 화면을 띄우지 않고 오류를 안내합니다. 로컬 서버는 브라우저 캐시를 사용하지 않도록 응답합니다.

직접 미리보기를 실행할 경우:

```sh
node build.js --preview
node scripts/serve.js 8000 --preview
```

배포 HTML을 저장소 안에 생성하거나 검사할 때만 `node build.js`와 `node scripts/check.js`를 사용합니다. GitHub 자동 빌드는 기존 방식대로 동작합니다.

`node scripts/serve.js`만 실행하면 포트 8080이며 이 명령 자체는 빌드하지 않습니다. 파일을 더블클릭하는 file:// 방식 대신 위 서버 주소를 사용하세요.

**생성된 HTML 직접 편집 금지.** 각 경로 index.html, 해시 파일명 assets/site.*·assets/lyric-quiz.*, sitemap.xml, build-manifest.json은 빌드 산출물입니다. 일반 링크로 이동하며 NEWS·ARCHIVE·GALLERY는 빌드 시 본문과 대체 데이터를 만들고 방문 후 최신 JSON을 읽습니다.

이전 해시 자산은 캐시된 HTML이 참조할 수 있어 유지합니다. 임의로 지우면 예전 페이지에서 퀴즈가 실행되지 않을 수 있습니다. 정리 도구는 이 파일들을 삭제하지 않습니다.

## HTML 병합 충돌과 미리보기

업데이트 ZIP에는 배포용 index.html이 없습니다(src/template.html은 편집 소스이므로 포함). 다만 v4.106까지의 미리보기 배치파일은 저장소 HTML을 다시 생성했고, GitHub 뉴스 자동 작업도 같은 HTML과 자산을 커밋했습니다. 로컬과 원격 변경이 갈라지면 HTML 마지막의 해시 파일 주소가 충돌할 수 있습니다.

v4.107 미리보기는 임시 폴더를 사용하므로 미리보기만 실행해도 HTML이 Git 변경 목록에 추가되는 문제를 예방합니다. 임시 출력은 체크아웃 경로마다 분리하며 원본 이미지·JSON을 중복 복사하지 않습니다. 서버 종료 후 기다릴 필요는 없습니다. 기존 미리보기 창이 있다면 먼저 닫고 새 배치파일을 실행하세요.

이미 GitHub Desktop에서 Resolve conflicts와 <<<<<<< HEAD가 나타났다면 실제 병합 충돌입니다. 미리보기는 이를 해결하는 도구가 아닙니다. 충돌 파일이 생성 HTML·manifest뿐인지, src/·data/도 포함되는지 먼저 확인하세요. 소스·수동 아카이브·자동 뉴스 내용을 적절히 병합한 뒤 배포용 `node build.js`로 HTML을 재생성하고 `node scripts/check.js`를 통과시킨 다음 병합을 완료합니다. main/HEAD 한쪽을 일괄 선택하지 마세요. src/template.html은 생성 HTML이 아니므로 충돌 내용을 직접 병합해야 합니다.

검사는 재생성 전에 충돌 표시를 확인합니다. 소스·데이터 충돌이 남아 있으면 빌드와 미리보기도 시작하지 않습니다. 이 변경은 이미 갈라진 Git 이력을 합치거나 자동 뉴스·데이터의 모든 병합 충돌을 없애는 것은 아닙니다. 업데이트 전 Fetch/Pull 후 덮어쓰기 순서를 유지하세요.

## 캐릭터 이미지 모음

GALLERY 상단의 “사진 / 캐릭터 이미지” 버튼으로 서로 다른 페이지를 이동합니다. 사진은 `/gallery/`, 캐릭터 이미지는 `/gallery/characters/`입니다. 사진 페이지에는 캐릭터 모음집을 함께 이어 붙이지 않습니다. 캐릭터 페이지에 14장의 그림을 6장씩(현재 3페이지) 표시하며, 클릭하면 원본 비율로 크게 볼 수 있습니다. 현재 메뉴는 선택 상태로 표시됩니다. 두 경로 모두 직접 접속·새로고침·브라우저 뒤로 가기·JS 미사용 이동을 지원합니다. 이전·다음 버튼, 좌우 방향키, 모바일 좌우 넘기기를 지원합니다. Escape 또는 닫기를 누르면 원래 카드로 돌아옵니다. “원본 보기”는 이미지 파일을 새 탭으로 엽니다.

페이지 번호는 주소의 `?page=2`처럼 유지되어 새로고침·뒤로/앞으로 가기를 지원합니다. 자바스크립트를 끄면 전체 그림을 볼 수 있습니다. 확대창의 이전·다음은 전체 14장을 순회하며 원본 보기로 긴 그림을 크게 열 수 있습니다.

그림 목록은 `src/data/character-gallery.json` 한 파일로 관리합니다. 각 항목은 고유 id, 이미지 주소, 실제 폭·높이, 사용 페이지 목록을 가집니다. 새 그림을 추가할 때 이 목록에도 등록하고 빌드하세요. 임의의 개별 제목을 붙이지 않으며 사용 페이지 링크만 표시합니다. 사용 페이지가 없으면 “캐릭터 일러스트”로 표시합니다. 기존 이미지 파일을 그대로 참조하므로 모음집을 위해 같은 파일을 다시 복사하지 않습니다. JS가 꺼져 있거나 dialog가 지원되지 않는 브라우저에서는 카드를 누르면 이미지 원본으로 이동합니다.

새 아카이브 그림은 `images/archive/seeya-archive-room.png`입니다. 기존 `seeya-archive-pixel.png`는 삭제하지 않고 “ARCHIVE · 이전 그림”으로 모음집에 보관합니다. 모의고사는 최근 수정본을 사용합니다. 여러 페이지에서 함께 쓰는 동일 그림은 모음집에 한 번만 표시합니다.

## 오늘 날짜의 씨야

TODAY의 첫 콘텐츠로 지난 연도 중 같은 월·일의 아카이브 기록을 보여줍니다. 한국 시간(Asia/Seoul) 기준이며 올해 및 미래 일정은 과거 회고에서 제외합니다. 연도별 최신순으로 모으고, 일치하는 기록이 없으면 빈 기록 안내를 표시합니다.

기준 자료는 기존 `data/archive.json` 하나입니다. 날짜가 정확히 월·일까지 있는 기록만 사용합니다. 영상·기사 게시일 기준과 잠정 날짜는 기존 표시를 유지합니다. 날짜 미확인·공연 시즌·취소·예정·숨김 기록은 제외합니다. 같은 ID는 한 번만 표시하며 일정표 링크는 카드에 노출하지 않습니다.

빌드 시 `src/data/site.json`의 `snapshotDate` 기준 본문을 생성합니다. 접속하면 실제 한국 날짜와 최신 JSON으로 갱신하고, 페이지를 계속 열어 두면 자정 이후 최대 약 30초 내에 날짜를 바꿉니다. 백그라운드 탭은 다시 열 때 확인합니다. 네트워크 오류 시 마지막으로 불러온 자료 또는 빌드에 포함된 자료를 사용합니다. JS를 끈 환경에서는 빌드 기준 날짜의 본문을 보여줍니다.

아카이브는 총 926건입니다. 예정 기록은 오늘 날짜의 과거 회고에서 제외됩니다. 과거 같은 날짜의 기록이 없으면 빈 기록 안내가 나타납니다.

# 공개 일정 알림 (2026-11-27)

- 신청 페이지: `https://seeya-fanpage.com/about/notifications/` (ABOUT → 일정 알림)
- API: `https://seeya-notifications.seeya-push-test.workers.dev`
- Worker/D1: `seeya-notifications`. 테스트 서버·DB·VAPID 키와 분리한다.
- 공개 PWA의 manifest와 아이콘을 사용한다. 알림 전용 서비스 워커 범위는 `/about/notifications/`이며 기존 루트·다이어리의 오프라인 캐시를 변경하지 않는다.
- 테스트 페이지 구독은 자동 이전하지 않는다. 공개 페이지에서 기기별로 새로 신청한다. 기존 아카이브 앱을 삭제할 필요는 없다.

## 운영

일정은 공개 `calendar/events.json`에서 읽는다. 한국 시간 기준, 확정·변경 상태인 당일 일정만 포함한다. 일정이 없으면 발송하지 않는다. 30분 단위로 선택한 시간에 하루 한 번 예약한다. 시작 버튼을 눌러 권한을 허용한 뒤에만 자동 알림을 활성화한다.

Cloudflare Cron이 매분 실행되어 PC가 꺼져 있어도 동작한다. 기기 수·망 상태·기기 절전 정책에 따라 지연될 수 있다. 매시 00/30분부터 5분 동안 예약을 보완하며, 예약 후 20분을 넘은 미발송 알림은 폐기한다. 모호한 전송 실패는 중복 방지를 위해 자동 재발송하지 않는다. 푸시 서비스 접수 성공은 실제 기기 표시 확인과 구분한다.

수신자는 구독 ID 첫 글자별 최대 16개 묶음으로 분산한다. 개별 전송은 인증된 자기 서비스 바인딩 요청에서 처리하고, 요청당 한 번의 암호화만 실행한다. 한 묶음은 최대 13번 연결하며 나머지는 다음 Cron에서 이어간다. DB에서 작업을 원자적으로 선점하고 `daily:날짜:기기` 키로 중복 예약을 막는다.

초기 운영 상한은 구독 3,000개이다. 등록 요청은 IP를 비밀키와 함께 해시한 시간별 버킷으로 15회, 테스트 알림은 기기별 한국 날짜당 20회 및 30초 간격으로 제한한다. 상한은 서비스 요금 한도를 보장하지 않으므로 Cloudflare 사용량도 확인한다. 운영 상황을 보고 상한을 조정한다.

## 메시지 형식

제목은 `씨야 일정 · 11월 28일`, 본문은 `시작–종료 · 방송사/장소` → `멤버` → `일정명` 순으로 줄바꿈한다. 종료 시간은 등록된 경우에만 표시한다. 방송사·장소는 캘린더의 시간 설명과 장소 필드에서 가져오며 추측하지 않는다. 여러 일정은 시간순 두 건까지 같은 형식으로 표시하고 나머지는 `외 N개 일정`으로 안내한다. 알림 본문과 `일정 자세히 보기` 버튼 모두 해당 일정/날짜 캘린더를 연다. 버튼과 줄바꿈의 실제 표시는 OS·브라우저에 따라 달라질 수 있다.

## 저장과 개인정보

구독 endpoint·푸시 암호화 공개키·알림 시간·발송 상태를 비공개 D1에 보관한다. 브라우저는 구독 소유권 토큰을 로컬에 저장한다. 다이어리·게임·편지·이름은 보내지 않는다. 원본 IP를 저장하지 않으며 제한용 해시는 24시간 뒤 정리한다. 발송 작업은 7일 뒤 정리하고, 해제 시 구독과 대기 작업을 삭제한다. 만료된 endpoint는 자동 알림을 중단한다.

## 재배포

`integrations/push-test`에서 실행:

```powershell
npm ci
npm test
npm run cloud:check
npm run public:check
npm run public:deploy
```

처음 설정할 때만 `cloud/schema.sql`과 `cloud/public-schema.sql`을 공개 D1에 적용한다. 기존 DB를 초기화하지 않는다. `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `PREVIEW_SIGNING_KEY`는 Wrangler secrets로 관리한다. `.runtime`, `.dev.vars`, `.wrangler`는 커밋하지 않는다. 기존 구독을 유지하려면 VAPID 키를 재생성하지 않는다.

공개 API는 `https://seeya-fanpage.com` Origin만 허용한다. 로컬 화면에서 연결 오류가 나오는 것은 예상된 동작이다. 로컬 기능 검증은 Miniflare 테스트를 사용하며 임의로 공개 CORS를 풀지 않는다.

배포 후 ABOUT 경로·서비스 워커·아이콘 응답을 확인하고, 공개 페이지에서 직접 신청 → 미리보기 테스트 알림 → 시간 변경 → 해제를 확인한다. 아이폰은 홈 화면에 추가한 웹 앱에서 신청한다. 기기 알림의 시스템 아이콘은 OS·브라우저가 결정하며, 설치한 앱과 브라우저 탭의 표시가 다를 수 있다.

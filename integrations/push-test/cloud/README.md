# Cloudflare 알림 테스트

메인 사이트·메뉴·공개 서비스 워커와 분리한 Workers + D1 테스트입니다.
사이트 페이지와 발송 서버 모두 Cloudflare에서 실행하며, 로컬 PC와 터널은 필요하지 않습니다.

## 구성

- `worker.mjs`: 허용한 정적 파일, 같은 출처 API, 구독 저장, 예약 발송.
- `schema.sql`: 구독 정보, 발송 대기 정보, 마지막 자동 실행 시각. 구독 해제 시 연결된 대기 정보도 삭제합니다.
- 공개 캘린더 `https://seeya-fanpage.com/calendar/events.json`에서 확정·변경 일정을 조회합니다. 실패 시 오래된 일정으로 대신 발송하지 않습니다.
- 한국 시간 30분 단위 선택. 설정 시각부터 5분 안에 잡을 만들고, 기기·날짜로 고정한 ID로 중복 생성을 막습니다.
- 테스트는 선택한 미리보기의 **서명된 원문**을 전송합니다. 1시간 유효하며 만료되면 새로고침합니다. 임의의 메시지나 URL을 서버에 지정할 수 없습니다.
- 테스트 전송은 약 15초 후 실행합니다. 요청의 백그라운드 작업이 종료되어도 D1에 남은 대기 건을 매분 cron이 처리합니다. 5분이 지나면 오래된 테스트는 보내지 않습니다.
- 푸시 서비스의 응답이 불명확한 경우 자동 재전송하지 않습니다. 중복 수신을 줄이는 대신 연결 실패 시 사용자가 다시 테스트해야 합니다. 서비스 전달 성공은 휴대전화 수신 확인과 다릅니다.
- 만료(404/410) 시 자동 알림을 해제합니다. 발송 대기·결과는 7일 후 삭제합니다.
- 테스트 기기는 최대 30개, 테스트 전송은 기기별 30초 간격입니다. cron에서 최대 8건씩 처리합니다. 운영 규모로 확대하기 전에 한도·부하·남용 방지를 재검토합니다.

## 배포

1. `npm ci`
2. `npm test` 및 `npm run cloud:check`
3. `wrangler d1 execute seeya-push-test --remote --file cloud/schema.sql` (새 DB 또는 스키마 변경 시)
4. `npm run cloud:deploy`
5. 첫 배포 시 Cloudflare secrets에 `PREVIEW_GATE`, `PREVIEW_SIGNING_KEY`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`를 설정합니다. 개인 키는 소스나 브라우저로 보내지 않습니다. 생성한 `.runtime/cloud-secrets.json`은 git에서 제외됩니다.
6. `/preview/<PREVIEW_GATE>/notifications/test/`에 접속합니다. 다른 경로는 404입니다. 비공개 경로는 로그인 대체가 아닌 소규모 테스트용 공유 제한입니다.

별도 Workers 테스트 주소로 옮기면 알림 권한과 구독도 다시 신청해야 합니다. 기존 메인 PWA에는 반영되지 않습니다.
Wrangler 로그인은 Workers·D1에 필요한 범위로만 요청했습니다. 유료 요금제 전환은 하지 않습니다.
cron 최초 설정은 Cloudflare에 전파되기까지 시간이 걸릴 수 있습니다.

## 실제 휴대전화 확인

1. 새 주소에서 알림 받기 → 1개·2개·4개 예시 선택 → 테스트 알림 받기.
2. 페이지를 닫거나 화면을 잠근 후 제목·본문·로고 확인. 다시 열어 전달 상태 확인.
3. 알림을 누르면 해당 날짜 캘린더, 한 일정인 경우 해당 일정 상세로 이동하는지 확인.
4. 자동 알림을 켜고 실제 일정이 있는 날 선택 시각에 수신 확인. PC와 기존 터널을 끈 상태로 확인합니다.
5. 알림 해제 후 다시 신청, 시간 변경, iPhone 홈 화면 앱 등은 기기별로 확인합니다.

`icon`에는 기존 아카이브 앱 아이콘, `badge`에는 공식 SEEYA 벡터 로고를 렌더링한 투명 단색 96px PNG를 지정합니다. OS가 붙이는 브라우저 이름·아이콘은 별개이며 기기마다 위치와 지원이 다릅니다.

## 검증

`cloud/test.mjs`는 workerd 및 임시 D1에서 서명 변조·만료, 다른 출처 요청, 구독 소유권, 속도 제한, 발송 큐, 동일 작업 동시 실행, 하루 중복 방지, 빈 일정, 구독 만료·해제를 검증합니다. 실제 외부 기기에 보내지 않습니다.

2026-11-27: 별도 workers.dev 배포·구독 저장과 실제 푸시 서비스 전달 성공을 확인했습니다. 클라우드의 fetch redirect 옵션은 manual을 사용하고 리다이렉트를 따라가지 않습니다.

최종 확인: 기존 로컬 Node 서버와 Quick Tunnel을 종료한 뒤에도 클라우드 API 200 응답을 확인했습니다. cron 실행 기록은 2026-11-27 21:42:27 KST에 확인됐습니다. 기존 8개 테스트와 실제 workerd/D1 통합 테스트가 통과했습니다. 메인 사이트 파일 및 main 배포는 수행하지 않았습니다.

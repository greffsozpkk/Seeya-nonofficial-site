# 씨야 일정 알림 — 독립 테스트

메인 사이트, 공통 서비스 워커, 다이어리 서비스 워커, 메뉴, 사이트 빌드는 변경하지 않습니다. `main`에 배포하지 않은 독립 테스트입니다. PC 없이 사용하는 Cloudflare 버전은 [클라우드 안내](cloud/README.md)를 참고하세요. 아래 내용은 로컬 Node 서버 실행 방법입니다.

## 실행

이 폴더에서 `npm ci --ignore-scripts` 후 `npm start`를 실행합니다. 기본 포트는 8210이며 127.0.0.1에만 바인딩합니다. 콘솔에 출력된 주소를 PC 브라우저에서 여세요. 다른 포트는 `PORT` 환경변수로 지정합니다.

휴대전화는 localhost에 접속할 수 없고 일반 LAN HTTP에서는 푸시를 신청할 수 없습니다. Cloudflare 공식 `cloudflared`를 설치한 후 `cloudflared tunnel --url http://127.0.0.1:8210 --no-autoupdate`로 임시 HTTPS 주소를 만듭니다. 콘솔의 로컬 주소에서 호스트만 터널 호스트로 교체하고 `/preview/…/notifications/test/` 경로는 그대로 유지합니다. 터널은 별도 계정이 필요 없으며 운영 배포용이 아닙니다. 서버는 명시한 테스트 파일과 API만 제공합니다. 저장소, 서버 소스, 런타임 파일을 제공하지 않습니다.

현재 실행 결과와 주소는 `.runtime/server.log`, `.runtime/tunnel-error.log`에서 확인할 수 있습니다. 시작 때마다 터널 호스트가 달라질 수 있습니다. 재시작 뒤에는 새 주소에서 다시 신청하세요. PC 절전·종료 또는 서버·터널 종료 시 테스트 발송이 중단됩니다. 중단은 해당 실행 터미널에서 Ctrl+C로 처리하고, 백그라운드 실행 시 기록해둔 해당 PID만 종료합니다.

## 기기 테스트

1. 갤럭시는 Chrome 등 지원 브라우저에서 HTTPS 주소를 엽니다. 아이폰은 Safari에서 열고 공유 → 홈 화면에 추가 후 설치된 ‘씨야 알림’을 엽니다(iOS 16.4 이상).
2. ‘알림 받기’를 눌러 기기 알림을 허용합니다.
3. ‘테스트 알림 받기’를 누르고 화면을 닫거나 잠근 뒤 15초 후 알림이 오는지 확인합니다.
4. 미리보기 알림을 누르면 예시에 표시된 날짜의 공개 캘린더로 이동합니다. ‘오늘 일정으로 받아보기’는 실제 로컬 일정이 있을 때만 활성화되고 알림에서 공개 캘린더로 이동합니다.
5. ‘일정 있는 날 하루 한 번 알림’을 켜고 받을 시간을 30분 단위로 선택합니다(기본 09:00, 한국 시간). 서버가 1분 간격으로 확인해 선택 시각부터 5분 이내에 기기별 하루 1회 발송을 시도합니다. 서버가 나중에 켜져도 이 시간대를 벗어난 알림은 뒤늦게 보내지 않습니다. 시간과 체크 여부는 새로고침해도 유지됩니다. 당일 이미 보낸 뒤 시간을 바꿔도 다시 보내지 않습니다.
6. ‘이 기기 알림 해제’는 서버 구독과 대기 중 테스트 발송, 브라우저 구독을 함께 제거합니다. 브라우저의 알림 권한 자체를 차단하려면 기기 설정을 이용합니다.

‘푸시 서비스에 전달했어요’는 전송 API 성공을 의미하며 사용자에게 표시됐다는 확인은 아닙니다. OS 알림 차단·집중 모드·절전·네트워크 영향은 별도로 확인하세요. 오늘 일정이 없으면 예시 알림만 전송할 수 있습니다. 테스트 알림은 30초 간격, 기기는 최대 30개로 제한합니다.

## 알림 내용과 클릭 목적지

- 일정 1개: `오늘의 씨야 · 멤버` / `시간 일정명`. 캘린더에서 발송 대상 날짜를 선택하고 해당 일정 상세를 펼친 목록 화면으로 연결합니다.
- 일정 2개 이상: `오늘의 씨야 · 일정 N개` / 시간·멤버·일정 두 줄, 나머지는 `외 N개 일정`. 해당 날짜의 캘린더 목록으로 연결합니다.
- URL에 `month`, `day`, `view=list`, `anniversaries=0`을 고정합니다. 한 개일 때만 `event`를 추가합니다. 다음 날 알림을 눌러도 원래 안내한 날짜로 이동합니다. 상세 화면에서 원본 방송·영상 링크를 선택할 수 있습니다.
- 테스트 페이지의 1·2·4개 일정 예시는 실제 과거 캘린더 자료에서 추출합니다. 화면에 날짜와 예시임을 표시하고 실제 발송 제목에도 `[예시]`를 붙입니다. ‘알림을 누르면 열리는 화면’ 링크로 발송 없이 목적지를 확인할 수 있습니다.
- 변경·취소 별도 알림과 기념일 선택, ABOUT 진입 링크는 아직 적용하지 않았습니다. 이번 변경도 독립 테스트 안에서만 동작합니다.

## 데이터와 동작

- `../../calendar/events.json`을 매번 읽고 KST 날짜, 취소·미확정 제외, 여러 날 일정, ID 중복 제거를 적용합니다. 기념일은 현재 테스트에서 제외합니다.
- 아침 일정은 기기별/날짜별 중복 방지를 저장합니다. 중복을 막기 위해 실패해도 당일 자동 재시도하지 않는 테스트용 정책입니다. 발송 도중 프로세스 종료 시 누락될 수 있습니다. 운영판에서는 전송 이력과 재시도 설계가 필요합니다.
- VAPID 키, 테스트 경로, 구독 주소·암호화 키, 설정과 전송 결과는 `.runtime/state.json`에 저장하고 Git에서 제외합니다. 백업이 필요하면 해당 파일을 비공개로 보관합니다. 공개 저장소나 브라우저 응답에 넣지 마세요.
- API는 기기별 비밀 토큰으로 자기 구독에만 접근하며, 교차 출처 변경 요청을 거부합니다. 푸시 전송 목적지는 브라우저 업체의 허용된 HTTPS 호스트로 제한합니다.
- 구독 정보는 발송을 위해 Google·Apple 등 기기의 푸시 서비스와 통신할 때 사용됩니다. 다이어리·게임·방명록·전화번호·이메일은 수집하지 않습니다.
- 별도 manifest ID와 경로 범위로 테스트 앱을 분리합니다. 기존 씨야 아카이브 앱 삭제가 필요하지 않습니다.
